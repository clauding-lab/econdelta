## Implementation and checks

- DSE now reads all summary fields from the official API in one request, validates `session.sessionDate`, converts million-BDT turnover, and retains the existing duplicate-session, calendar-observation and anomaly checks.
- DAM's deterministic parser accepts the portal's dated JSON response and the browser's `<pre>` JSON wrapper. It validates the pinned commodity and official retail-unit ID, row date, latest feed period and numeric range. Observation metadata records prices as `BDT/kg` or `BDT/4 pieces`, not just the product's sale unit. DAM indicators have no LLM extraction fallback, so a rejected exact-product period cannot inherit a sibling commodity's date or value. The old ticker path now requires an actual report date and rejects a conflicting banner date.
- Commodity history rows with no ticker-specific quote date remain undated; they no longer borrow a sibling ticker's bundle date. The captured 24 Sep Brent move is a regression fixture and still returns the existing whole-bundle hold result.
- The public DSE capture and the filtered DAM ticker/product-definition captures are stored under `tests/fixtures/`. The larger raw evidence and its provenance remain in the shared repair workspace.
- Focused result: 157 passed across fetch containment, DSE, DAM, source-date propagation, observation quarantine and aggregator alerts. The full suite passed 2,126 tests with 91 skipped; it overlapped a small refactor of the DAM unit-map tuple, so the affected final-tree parser/snapshot tests were rerun separately (42 passed). Ruff and `git diff --check` passed, and the generated indicator catalog was refreshed.
- No Supabase or other production data was changed, and no push or deployment was performed.
